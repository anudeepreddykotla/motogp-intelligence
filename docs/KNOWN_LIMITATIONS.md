# Known Limitations

- No existing MotoGP Java, Go, frontend, ingestion, database, or deployment implementation was found in this repository.
- The initial repository has no confirmed historical dataset.
- Live timing access is not established and must not be assumed.
- Detailed telemetry such as throttle, braking, lean angle, suspension, and GPS is not guaranteed to be public or licensed.
- Historical lap, sector, tyre, and weather fields may be incomplete by season and provider.
- News ingestion, article summaries, and document embeddings depend on publisher permissions and source terms.
- ML models cannot be considered valid until chronological evaluation, baselines, calibration, and versioned artifacts exist.
- AI responses cannot be considered grounded until structured tools, retrieval, citations, and failure handling are tested.
- License terms for datasets, third-party APIs, and the project itself remain unresolved.
- Deployment target, secret management, and operational cost limits remain unresolved.
- User authentication, JWT issuance, refresh-token rotation, and role management are not implemented in Phase 0.
- The local Compose fallback token is intentionally development-only and must be replaced through environment configuration before shared or deployed use.
- CI validates individual Java, Python, frontend, and frontend-container builds; full Compose integration remains an environment-level verification step.
- Phase 1.1 includes only the deterministic `fixture-historical` provider; no external API, web-scraping adapter, or licensed historical dataset is integrated.
- Provider identity mapping is an internal Java service boundary and is not yet exposed as a public or frontend API.
- Identity mappings validate entity existence against the approved allowlisted domain tables; the generic `internal_id` design intentionally does not use polymorphic foreign keys.
- Phase 1.3 implements only deterministic fixture ingestion for affiliations, rider entries, sessions, classifications, laps, and race positions; it does not include sectors, tyres, weather, standings, telemetry, raw-payload capture, or public ingestion APIs.
- No authorized external historical provider is integrated, so fixture records must not be treated as production MotoGP data.
- The read-only historical endpoints are temporarily unauthenticated because user authentication is not implemented; deployment must place them behind the approved authentication boundary.
- Compose integration verification requires a reachable database endpoint; the local host currently exposes an unrelated PostgreSQL instance on port 5432.
- Source versions are currently immutable per logical provider/entity/external-ID record. Version history, raw-payload association updates, and corrected-provider-data workflows are future work; a changed non-null source version is rejected.
- Lap `observedAt` is intentionally nullable when the provider supplies timing without an observation timestamp. API consumers receive JSON `null`; timestamps are not inferred.
- Phase 1.4 completes read-only season, event, session, classification, lap, position, and session-scoped rider-comparison APIs. All historical list responses expose limit/offset/hasNext metadata but do not expose total counts or cursor links.
- Comparison is limited to persisted classifications for one session and 2–4 riders; cross-event/circuit analytics and derived performance statistics belong to a later analytics phase.
- Phase 1.5 provides a read-only responsive frontend for the historical race journey. It uses the Java `/api` proxy, labels fixture/demo session data when reported, and does not expose a separate frontend pagination control when an API response reports `hasNext`.
- Phase 1.6 expands the local fixture archive to 2 seasons, 2 manufacturers, 4 teams, 10 synthetic riders, 2 circuits, 4 events, 12 sessions, 120 classifications, 400 laps, and 440 position snapshots. These records are synthetic demonstrations, not real MotoGP history.
- The Phase 1.6 refresh runner is intentionally a local operator mechanism for `fixture-historical` only. It rebuilds fixture-owned race data when values or provenance differ, preserves matching fixture reference identities where possible, and does not provide a general provider reconciliation framework.
- Phase 2.1 provides only the Java RSS/Atom ingestion foundation. No production feed URL is enabled, no publisher-specific permission has been asserted, and no public news listing, ranking, enrichment, summary, or entity-linking API exists yet. Stored content is limited to metadata and configured permitted excerpts; complete articles are never mirrored.
